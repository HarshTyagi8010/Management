# Security Policy

## Reporting a vulnerability
Please don't report security problems in public issues or pull requests.

Send reports privately to the project maintainers. Use the security contact the project owner configures before pilot, such as a dedicated mailbox or GitHub private vulnerability reporting once the repository is hosted. Until one exists, contact the project owner directly.

Please include the affected component, steps to reproduce, and impact. Don't access other tenants' data, run denial-of-service tests, or use social engineering.

We aim to acknowledge reports within 3 business days and to agree on a fix timeline based on severity.

## Supported versions
Pre-release. Only the `main` branch receives fixes.
